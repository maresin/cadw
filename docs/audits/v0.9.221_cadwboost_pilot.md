## §1. CadwBoost verdict: TRUE OOC

| n | peak | per_row |
|---|---|---|
| 1 000 | 4.26 MB | 4 264 B (startup-dominated) |
| 5 000 | 0.74 MB | 147 B |
| 20 000 | 3.34 MB | 167 B |
| 50 000 | 11.51 MB | 230 B (allocator warmup) |
| 100 000 | 3.06 MB | 31 B |
| 200 000 | 4.72 MB | 24 B |

**Ratio (200k / 50k) = 0.41x** — peak **decreases** as n grows (allocator
warmup amortized). True OOC per STABILITY §2.1 (ratio < 2.0 at 4x n).

**Mechanism** (`cadwboost/ooc.py`, 257L):
- `codes_mm (n,d) uint8` + `y_mm (n) f64` + `pred_mm (n) f64` — all
  `np.memmap`
- `MAX_OOC_BATCH = 20_000` (fixed, independent of n)
- `MAX_OOC_SAMPLE = 50_000` (reservoir for quantile binning)
- Per-level histograms `G/H = np.zeros((n_leaves, d, n_bins))` — bounded
  by tree shape, not n
- Splits: symmetric only (leaf_wise needs per-node hist → P1)

**Difference vs `cadw.ml.gbdt` (DEC-065, v0.9.172):** gbdt stores
pred/grad/hess/cur_leaf/nan_mask (~20-24 B/row); memmap dirty pages
counted in RSS (`madvise(MADV_DONTNEED)` insufficient). CadwBoost uses
per-level histograms (never materializes per-row scores in RAM; only
batch=20k transient + 50k reservoir).

## §2. GBDT family classification correction

`cadw.ml.gbdt` measured P47b (n=1k..20k, median single run):
- Warmup dominates at n=1000 (4 MB; baseline Python + Arrow)
- Realistic n=5000: 0.58 MB (116 B/row)
- n=20000: 4.42 MB (221 B/row — 2x warmup drift)

**Ratio 1.10x** at 20x n looks OOC-ish, but warmup masks the leak.
DEC-065 controlled test (n=5k→200k, 40x, median-of-3) measured **ratio
24-36** (linear). Honest verdict: **partial OOC, not true**.

**Classification: 6 achievable GBDT cards → debt** (intrinsic until
posix_fadvise refactor OR CadwBoost promote):
- `GBDT` (A_classification)
- `GBDT_multiclass` (A_classification; also cur_leaf_c unmemmapped)
- `GBDT_L2` (A_classification)
- `GBDT_scale_pos_weight` (A_classification + E_anomaly dup)
- `GBDTForecaster` (D_time_series; deferred horizon + lag matrix)

Not in scope: `GBDT_threshold`, `GBDT_pinball` (status=None, no code).
