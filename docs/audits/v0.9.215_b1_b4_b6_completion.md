## §2. Agglomerative implementation

`fit_agglomerative` (cadw/ml/agglomerative.py, ~280 lines):
- All 4 linkages via scipy.cluster.hierarchy dense linkage.
- Exact sklearn parity (ARI=1.0 on 4 linkages, 2 clusters).
- Materialize X (n*d) + scipy linkage Z (n^2) — O(n^2) intrinsic.

**Why dense-only (not k-NN + MST):**
- Initial attempt: single-linkage via k-NN graph (knn_query_stream) +
  MST + cut. Failed at n=60 (2 separated clusters, k=16 insufficient
  to connect 30-pt clusters → MST forest with 2 components → cut 1
  edge increases components to 3, not 2).
- Correct k for single-linkage OOC would need k ≈ min cluster size
  (30 in this case), unknown a priori.
- Deferred: approximate single-linkage via k-NN + MST as opt-in
  `mode='approx'` v0.9.216+ (HDBSCAN-style, loses exact parity at
  high k_neighbors).

## §6. MH/NUTS fix rationale

Both updated to honest `debt` (permanent):
- **MetropolisHastings**: full-data likelihood per accept/reject step
  is intrinsic. Cannot stream without subsample approximation.
- **NUTS**: Hamiltonian trajectories require full-data gradient per
  leapfrog step (typically 10-100 per sample).

Approximations noted in ooc_alternative:
- **SGLD/SGHMC** (mini-batch MCMC) — v0.9.216+.
- **VI family** (MeanFieldVI, SVI, BlackBoxVI) — separate implementation
  in v0.9.216+; these ARE streamable (chunked CAVI).
