**Rules (13.4/174):**

     "not found".

3. **Self-compile check before run:**
   - `uv run python -c "import py_compile; py_compile.compile(

**Эпизод 175 (memory formula validity scope).** v0.9.3c: P-D2
из v0.9.2 audit.

**Bug.** `_local_dedup` guard `check_state(1.5 * table.nbytes)`
был выведен из prototype v0.8.11a: int64 keys, K<<N, measured
peak 0.23x table. Экстраполяция на **string keys, K=N** дала
7.5x underestimate (real 11.26x). Consequence: partition passes
1.5x check, but real peak 11x -> OOM вместо MemoryLimitExceeded.

**Правило (13.4/175, расширение 128, 158, 173):**

- **Memory formula scope must be measured, not extrapolated.**
  Prototype on int K<<N не доказывает что formula holds для
  string K=N. Kernel cost depends on: dtype (fixed-width vs
  variable-length), cardinality (K vs N), and internal BufferBuilder
  geometric growth (2x peak).
- **Bench matrix for each guard:**
  - dtype: int / float / string (at least)
  - cardinality: K<<N / K=N/2 / K~N
  - table size: small / medium / large
  Формула должна быть conservative на **worst cell** матрицы,
  не average.
- **`pc.dictionary_encode` is not O(table.nbytes).** For variable-
  length types it copies every value + builds offsets + indices +
  hash table. Peak = table.nbytes + K*(avg_len+8)*2 + 
  4*N (indices) + hash table + BufferBuilder 2x. Simplify: 12x
  table.nbytes for string subset (measured, bench-backed).

**Backlog (11.6):**
- Audit all `check_state` formulas — grep `* table.nbytes`,
  `* grouped_table.nbytes`, etc. Each should have bench matrix
  source in docstring, not single-cell extrapolation.
- Sample-based K_est tightening for dedup: for K<<N strings,
  could use 2.5x instead of 12x via `count_distinct(sample)`
  extrapolation. v0.9.4.

**Связанные:** 13.4/128, 158, 173, **P-D1 v0.8.11a** (guarded
int path only; strings edge case deferred to v0.9.2 audit).

**Эпизод 176 (int arithmetic silent truncation).** v0.9.3d: C2
из v0.9.2 audit.

**Bug.** `StdOp.update`:
```python
mean_b = pc.mean(arr, skip_nulls=True).as_py()  # 2.5
diff = pc.subtract(arr, pa.scalar(mean_b, type=arr.type))
```
Для int64 arr: `pa.scalar(2.5, type=int64)` = **2** (silent
truncation, no warning). M2 computed from wrong deviations ->
wrong std. `[1,2,3,4]`: buggy sqrt(2) ~= 1.414, correct
sqrt(5/3) ~= 1.291.

**Почему не поймали в v0.1.0 (исходный):** `test_reduce.py::
test_std_invariant` использует `make_iter(data, bs)` с default
`type=pa.float64()` — int-путь не тестировался. Float path всегда
правильный (`pa.scalar(2.5, type=float64)` exact).

**Правило (13.4/176, расширение 163, 175):**

- **Int arithmetic truncates silently.** `pa.scalar(float, type=int)
  обрезает. `np.array(int) / n` даёт float. `pc.divide(int, int)` —
  float. Но `pa.scalar(x, type=int_type)` — truncate.
- **Casting policy при arithmetic с derived values** (mean, median,
  quantile): всегда cast array to float64 перед scalar op.
  Derived values fractional by nature; using original int type for
  scalar is always wrong.
- **Test matrix для числовых ops:** int64 / float64 / int32
  (at least). Float-only tests hide truncation bugs.

**Backlog (11.6):**
- Grep `pa.scalar(.*type=arr.type)` в cadw/ — каждое место
  проверить: если scalar — derived value (mean/median/etc), нужен
  explicit float64 cast. `PredicateFilter.mask_for_batch` — separate
  case (C3, user value не derived; correct behavior — validate type
  upfront).
- Audit numeric ops (`SumOp`, `MinMaxOp`, `MeanOp`, `CovarianceOp`,
  `HistogramOp`) — float64 cast присутствует везде кроме `StdOp`
  (fixed здесь).

**Связанные:** 13.4/163 (domain validation), 175 (memory formula
scope), P-CV1 (small-N hides O(N) bugs) — same class
«implementation mismatch с contract», не поймали small-numeric
test'ом.

**Эпизод 177 (shadowed def - dead code + dead optimization).**
v0.9.3e: C1 из v0.9.2 audit.

**Bug.** `_local_groupby` (cadw/ops/groupby.py):
```python
def _read_for_resplit(): ...    # optimization: reuse `table`
def _read_for_resplit(): ...    # shadows first (identical name)
```
Второй def перекрыл первый. Первый (optimization) никогда не
выполнялся. Optimization не активна (suboptimal disk re-read) и
не тестировалась.

**Правило (13.4/177, расширение 152, 160, 167):**

- **Duplicate same-name def в same scope = всегда shadowing**,
  не fallback. Python не «попробует сначала один, потом другой»;
  второй безусловно переопределяет первый.
- **Dead code + dead optimization.** Если optimization shadowed —
  она не работает. Future reader, глядя на первый def, думает
  «optimization есть». Должна быть либо активна (delete second),
  либо удалена (delete first + backlog). Оставлять = misleading.
- **AST guard для same-scope duplicates:** `test_no_shadowed_def_
  ast` — для каждой FunctionDef в теле другой функции: name
  уникален. Extended: ClassDef methods, module-level defs — same
  check.

**Урок (meta).** Text-match как способ fix'а упал в v0.9.3a
6 раз (unicode em-dash `—` vs ASCII `->`, escape `\n`, `'''`
vs `"""` in templates). **AST-based fix** (`ast.walk` +
`node.lineno`/`end_lineno`) — прецизионный и content-agnostic.
Для любого deletion/insertion по структуре кода использовать
AST, не regex/string.

**Backlog (11.6):**
- Restore optimization: `_read_for_resplit` reuse `table` если
  available. Prototype needed (correctness: in-memory split == disk
  re-read). v0.9.4.
- Extend `test_no_shadowed_def_ast` на весь `cadw/` — grep AST
  на duplicate top-level defs, duplicate method names per class.
  Одна проверка всех — cheap, high-value.

**Связанные:** 13.4/152 (stale), 160 (stale regex round 5),
167 (partial migration).

### 13.5. Открытые вопросы

1. `unique` через `Reduce` при `K ≤ памяти` (порог калибруется бенчмарком).

3. Формат спилла для агрегатов: struct vs два массива (`sum`, `count`).
4. Порог compaction: фиксированный процент или адаптивный.
5. Параллелизм чтения: детектировать SSD/HDD.
6. `to_batches(format='torch'/'numpy')`: в итераторе или в операции.
7. Skew-стратегия: изоляция vs рекурсия с новым seed.
8. `shape` на отфильтрованном `CadwDataFrame`: оставить upper bound или считать точно (сканирует).
