# v0.9.49 — BUG-1 report: value_counts multi-chunk

Branch: `pingis/dev-audit`. Base: `4e7e614` (v0.9.48.9).

## Root cause (confirmed)

In `cadw/ops/groupby.py::_groupby_with_skew`, `all_results` mixes two
aggregation paths whose output schemas disagree on `__vco_sum`:

- **light path** (`_local_groupby` → `pa.Table.group_by(...).aggregate`)
  preserves the input integer dtype of the ones-column → `__vco_sum: int64`.
- **heavy path** (`_accumulate_heavy` → `_accum_to_table` →
  `_empty_result_schema`) declares every non-count aggregation as
  `float64` → `__vco_sum: double`.

When a multi-chunk frame produces light partitions and a heavy key, the
final `pa.concat_tables(all_results)` (line 741) rejects the mismatch
(observed exactly: 5 int64 + 1 double in the reproducer). Single-chunk
frames either never trigger skew isolation or never mix paths, so the bug
is chunk-size dependent.

## Fix approach

Before `pa.concat_tables`, align every result to the schema of the first
result via a **safe** `Table.cast(target_schema)`:

- counts stay `int64` (matches pandas `value_counts` dtype and keeps M2
  parity),
- integral float partials round-trip exactly (float64 exact up to 2^53),
- **no** `promote_options` — it would mask unrelated schema mismatches.
- `_empty_result_schema` path unchanged; empty input still returns the
  documented empty schema.

Fix site: `cadw/ops/groupby.py`, `_groupby_with_skew`, immediately before
`pa.concat_tables`. No change to `_aggregations.py` needed.
