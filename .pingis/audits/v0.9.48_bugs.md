# v0.9.48 — bugs discovered during discovery (NOT fixed here)

## BUG-1: `CadwDataFrame.value_counts` crashes on multi-chunk frames (categorical column)

- **Discovered:** 2026-10-25 during Section O (EDA) bench for O1
- **Severity:** medium (chunk-size dependent; single-chunk works)
- **File:line:** `cadw/ops/groupby.py:741` — `pa.concat_tables(all_results)` in `_groupby_with_skew`
- **Called from:** `cadw/dataframe/_aggregations.py:82` (`value_counts` -> `_gba` -> `groupby_aggregate` -> `_groupby_with_skew`)

### Reproducer

```python
import numpy as np, pyarrow as pa, pyarrow.parquet as pq
from cadw import CadwDataFrame, MemoryGuard

n = 100_000
rng = np.random.default_rng(0)
tab = pa.table({
    **{f"c{i}": pa.array(rng.normal(size=n)) for i in range(10)},
    "cat": pa.array([f"g{j % 20}" for j in rng.integers(0, 20, size=n)]),
})
p = "/tmp/src.parquet"; pq.write_table(tab, p)
df = CadwDataFrame.from_parquet(
    p, "/tmp/ds", chunk_size=50_000,          # <-- MULTI-CHUNK
    memory_guard=MemoryGuard(max_memory_mb=500), spill_dir="/tmp/spill",
)
df.value_counts("cat")                        # raises ArrowInvalid
```

### Suspected root cause

Per-chunk partial sums for the `__vco_sum` column are typed `int64` on some
chunks (count-only path) and `double` on others (sum path). The final
`pa.concat_tables` requires identical schemas, so it fails when both
path variants are hit across chunks. Single-chunk frames never mix, so the
bug is chunking-dependent.

### Workaround

Single-chunk (`chunk_size >= n`) avoids the crash.

### Follow-up

**v0.9.48.x** — unify the partial-aggregate dtypes before `concat_tables`
(coerce `__vco_sum` to `float64`, or cast per-chunk to the declared
schema of chunk 0). Add a regression test with `chunk_size < n` on a
categorical column.

**Not fixed in v0.9.48** — discovery task, cards only, no code in cadw/.
